# Зависимости и связи между сущностями

## Обзор архитектуры данных

### Основные сущности и их зависимости

```
User (Пользователь)
├── Projects (Проекты)
│   ├── Tasks (Задачи)
│   └── Estimates (Сметы)
│       └── EstimateItems (Позиции сметы)
├── Products/Services (Товары/Услуги)
│   └── StockMovements (Движения склада)
├── Contractors (Контрагенты)
└── TimeEntries (Учет времени)
```

## Детальный анализ зависимостей

### 1. Project (Проект)
**Зависит от:**
- User (владелец)
- Contractor (опционально)

**Имеет зависимые:**
- Tasks (задачи проекта)
- Estimates (сметы проекта)
- TimeEntries (записи учета времени)

**Критичность:** ВЫСОКАЯ
- Удаление проекта должно проверять наличие связанных задач и смет
- Изменение контрагента проекта не обновляет контрагента в существующих задачах

### 2. Task (Задача)
**Зависит от:**
- User (владелец)
- Project (обязательно с версии 2.0)
- Contractor (опционально)
- EstimateItem (опционально)

**Имеет зависимые:**
- TimeEntries (учет времени)
- Product reservations (резервы товаров)

**Критичность:** ВЫСОКАЯ
- Задача не может существовать без проекта
- При удалении задачи нужно снимать резервы товаров

### 3. Estimate (Смета)
**Зависит от:**
- User (владелец)
- Project (обязательно)
- Contractor (опционально)

**Имеет зависимые:**
- EstimateItems (позиции сметы)
- Product reservations (при статусе approved)
- TimeEntries (учет времени по услугам)

**Критичность:** ВЫСОКАЯ
- При изменении статуса сметы меняются резервы товаров
- Удаление сметы должно снимать все резервы

### 4. Product/Service (Товар/Услуга)
**Зависит от:**
- User (владелец)
- Other Products (для составных услуг)

**Имеет зависимые:**
- EstimateItems (использование в сметах)
- StockMovements (история движений)
- Task reservations (резервы под задачи)

**Критичность:** СРЕДНЯЯ
- Удаление товара с активными резервами должно быть заблокировано
- Изменение цены не влияет на существующие сметы (snapshot)

## Обнаруженные проблемы

### 1. Отсутствие каскадной защиты
- ❌ Проект можно удалить при наличии задач и смет
- ❌ Контрагента можно удалить при наличии связанных проектов

### 2. Несогласованность данных
- ⚠️ При изменении контрагента проекта, задачи сохраняют старого контрагента
- ⚠️ При удалении товара не проверяются активные резервы

### 3. Отсутствие транзакционности
- ❌ Операции создания сметы с резервированием товаров не атомарны
- ❌ Нет откатов при частичных ошибках

### 4. Проблемы с undefined полями
- ✅ Решено через cleanObject утилиту
- ⚠️ Не все API методы используют cleanObject
