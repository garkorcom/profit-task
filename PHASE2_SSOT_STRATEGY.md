# Фаза 2: Стратегия Унификации (SSOT) - Документация

## Обзор реализации

В рамках Фазы 2 была создана комплексная система унификации управления задачами, которая объединяет EstimateTask (Pre-construction) и ProjectTask (Execution) в единую точку входа (Single Source of Truth).

## Ключевые компоненты

### 1. Унифицированная типизация (`/src/types/unified-task.types.ts`)

**Решает проблему:** Фрагментация типов между EstimateTask, ProjectTask и Task

**Ключевые особенности:**
- **Discriminated Union типы** для безопасной работы с разными типами задач
- **Type Guards** для проверки типа задачи во время выполнения  
- **Базовый интерфейс BaseTask** с общими полями
- **Специализированные интерфейсы** EstimateTaskUnified и ProjectTaskUnified
- **Валидация переходов статусов** с константами TASK_STATUS_TRANSITIONS
- **DTO типы** для создания и обновления задач

```typescript
// Пример использования
export type UnifiedTask = EstimateTaskUnified | ProjectTaskUnified;

export const isEstimateTask = (task: UnifiedTask): task is EstimateTaskUnified => {
  return task.phase === 'pre_construction';
};
```

### 2. Централизованный хук управления (`/src/hooks/useTaskManagement.ts`)

**Решает проблему:** Дублирование бизнес-логики в разных компонентах

**Функциональность:**
- **CRUD операции** с унифицированным API
- **Фильтрация и поиск** с поддержкой всех типов задач
- **Валидация данных** на уровне хука
- **RBAC интеграция** с проверкой разрешений
- **Статистика и аналитика** в реальном времени
- **Управление статусами** с валидацией переходов

```typescript
const {
  tasks,
  createTask,
  updateTask,
  changeTaskStatus,
  statistics
} = useTaskManagement();
```

## Архитектурные решения

### Discriminated Union Pattern
Использование поля `phase` как дискриминатора позволяет TypeScript точно определить тип задачи:

```typescript
if (task.phase === 'pre_construction') {
  // TypeScript знает, что это EstimateTaskUnified
  console.log(task.includeMode); // ✅ Доступно
  console.log(task.plannedCost); // ❌ Ошибка компиляции
}
```

### Context + Hook Pattern
Разделение логики между useTaskManagement (бизнес-логика) и TaskConfigProvider (UI конфигурация) обеспечивает:
- Переиспользуемость логики
- Легкую кастомизацию UI
- Тестируемость компонентов

### Type-Safe API Design
Все DTO типы строго типизированы и валидируются:

```typescript
// Компилятор проверит наличие обязательных полей
const estimateTaskData: CreateEstimateTaskDto = {
  phase: 'pre_construction',
  name: 'Task name',
  estimateId: 'est_123',
  includeMode: 'COGS',
  plannedHours: 8
};
```

## Интеграция с существующим кодом

### Совместимость
- Новые типы совместимы с существующими интерфейсами
- TaskStatus из taskApi.ts переиспользуется
- Существующие компоненты могут постепенно мигрировать

### Путь миграции
1. Импорт унифицированных типов
2. Замена локальной логики на useTaskManagement
3. Использование TaskConfigProvider для UI конфигурации
4. Постепенная замена компонентов на унифицированные

### 1. Единый источник истины (SSOT)
- Одна точка входа для всех операций с задачами

- Хуки переиспользуются в разных контекстах

### 4. Масштабируемость
- Легко добавлять новые типы задач
- Простое расширение функциональности
- Модульная архитектура
