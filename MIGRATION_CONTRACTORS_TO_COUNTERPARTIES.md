# Миграция Contractors → Counterparties

## 📋 Обзор

В системе существовало дублирование функционала:
- **Старая система**: `Contractor` (простая модель)
- **Новая система**: `Counterparty` (расширенная модель с полной функциональностью)

## 🎯 Что сделано

### 1. ✅ Исправлены TypeScript ошибки
- Добавлена правильная типизация в `cleanDuplicateCounterparties.ts`
- Исправлены проблемы с доступом к свойствам объектов

### 2. ✅ Создана утилита миграции
**Файл**: `src/utils/migrateContractorsToCounterparties.ts`

Функции:
- `migrateContractorsToCounterparties()` - переносит contractors в counterparties
- `checkContractorsForMigration()` - проверяет наличие старых данных
- `deleteAllContractors()` - удаляет старые записи после миграции

### 3. ✅ Добавлен интерфейс миграции
В разделе "Контрагенты" добавлена кнопка **"Миграция Contractors"** которая:
- Проверяет наличие старых данных
- Показывает список для миграции
- Переносит данные с проверкой дубликатов
- Удаляет старые записи после успешной миграции

### 4. ✅ Обновлена навигация
- Роуты `/contractors` автоматически перенаправляют на `/counterparties`
- Обновлены ссылки в навигации

## 📊 Сравнение систем

| Функция | Contractors (старая) | Counterparties (новая) |
|---------|---------------------|------------------------|
| Контакты | 1 контактное лицо | Множество контактов с ролями |
| Адреса | 1 адрес | Множество адресов (юр., факт., доставки) |
| Финансы | Базовые банк. реквизиты | Полная финансовая информация |
| Документы | Нет | Compliance документы с датами |
| Статусы | Нет | Жизненный цикл со статусами |
| КПП | Есть | Полная интеграция с проектами |
| Роли | supplier/customer/both | customer/vendor/partner/subcontractor |
| Взаимодействия | Нет | История взаимодействий |
| Риски | Нет | Оценка рисков |

## 🚀 Как выполнить миграцию

1. Откройте раздел **"Контрагенты"** (`/counterparties`)
2. Нажмите кнопку **"Миграция Contractors"** в верхней панели
3. Подтвердите миграцию
4. Система автоматически:
   - Перенесет все данные
   - Пропустит дубликаты
   - Удалит старые записи

## ⚠️ Важно

### Что переносится:
- ✅ Название компании
- ✅ ИНН и КПП
- ✅ Контактное лицо
- ✅ Телефон и email
- ✅ WhatsApp и Telegram
- ✅ Адрес
- ✅ Банковские реквизиты
- ✅ Заметки
- ✅ Тип (supplier → vendor, customer → customer)

### Что НЕ переносится:
- ❌ Связи с задачами (требует отдельной миграции)
- ❌ История изменений

## 🔍 Проверка дубликатов

При миграции система автоматически проверяет:
1. **По ИНН** - если ИНН уже существует, запись пропускается
2. **По названию** - если название совпадает, запись пропускается

## 🛠️ Дополнительные функции

### Поиск дубликатов
Кнопка **"Найти дубликаты"** - анализирует базу на наличие дублирующихся контрагентов

### Удаление дубликатов  
Кнопка **"Удалить дубликаты"** - удаляет старые дубликаты, оставляя самые новые записи
